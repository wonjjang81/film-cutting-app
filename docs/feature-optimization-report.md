# 필름 재단 계산기 추가 기능 최적화 및 고도화 보고서

작성일: 2026-08-22  
대상 브랜치: `codex/continuous-roll-remnants`  
앱 버전: `1.0.0`

## 1. 요약

기존 앱의 핵심 생산 workflow를 현재 연속 롤 계산기 구조에 통합했다. 입력·그룹 배치·자투리 재사용·재단 완료·견적·프로젝트 관리·설정 기능을 하나의 로컬 저장소 모델로 연결했으며, 원단 절약을 우선하는 계산 경로를 유지했다.

이번 고도화의 핵심 결과는 다음과 같다.

- 프로젝트 관리 탭을 추가해 저장 작업 검색·열기·이름 변경·삭제 지원
- 그룹별 병합 번호와 혼합 규격 롤 계산 추가
- 병합 롤 저장 단위(`SavedMergedCuttingJob`), 그룹별 색상 도면·조각 상세·병합 재단 완료 체크 추가
- 순차 그룹 배치의 원자적 재고 확정과 병합 롤·자투리 중복 확정 차단
- Cloudflare Pages Functions·D1 API 골격과 로컬/서버 저장소 전환 어댑터 추가
- 설정 화면의 Cloudflare API·D1 상태 확인 및 수동/푸시 배포 workflow 추가
- 그룹별 필름명·원단 단가·시공 단가 저장 및 견적 반영
- 수동 배치의 5mm 스냅, 경계 제한, 충돌 방지, 90도 회전, 캔버스 드래그 추가
- 여러 저장 작업을 합산하는 통합 견적과 회사 정보 자동 반영
- 로컬 작업자 프로필, 앱 버전 확인, GitHub 릴리스 확인 추가
- JSON 백업·복원과 기존 회사명 저장값 마이그레이션 지원

## 3. 기술 고도화 내용

### 3.1 저장소 모델 통합

`LibraryDocument`를 기준으로 프리셋·저장 작업·병합 작업·자투리 재고를 통합했다. 저장 작업에는 재단 완료 상태, 조각별 완료 ID, 재고 확정 상태, 필름명, 그룹별 단가를 선택적으로 저장해 기존 데이터와 호환되도록 했다. 병합 작업은 원본 작업 ID와 배치 좌표를 포함하는 하나의 저장 단위로 기록한다.

Cloudflare 전환을 위해 `/api/health`, `/api/library` Pages Functions와 D1 `libraries` 테이블 스키마를 추가했다. 앱은 `EXPO_PUBLIC_CLOUDFLARE_API_URL`이 설정된 경우에만 서버 어댑터를 사용하고, 미설정 시 기존 AsyncStorage를 유지한다.

저장소에는 다음 안전장치가 적용되어 있다.

- JSON 구조 및 필드 타입 검증
- 잘못된 데이터 경고 및 안전한 초기화
- 작업·프리셋·자투리 ID 검증
- 재고 변경 시 `updatedAt` 기반 stale 데이터 차단
- 여러 조각의 재고 delta를 최초·최종 inventory 비교로 합산하는 원자적 그룹 확정
- 병합 롤 완료와 원본 조각 재고 확정의 상호 배타적 guard
- 부분 자투리 교체 시 원본 동일성 검증
- JSON 백업 불러오기 전 문서 검증

### 3.2 원단 절약 계산

단일 조각은 `planWithRemnants`로 자투리를 먼저 평가하고, 부족한 수량만 새 롤에서 계산한다. 여러 조각은 `planGroupedPieces`가 앞 조각의 재고 결과를 다음 조각에 전달한다.

병합 그룹에는 `optimizeMergedRollLayout`을 적용해 서로 다른 폭·길이 조각을 하나의 혼합 롤에 배치하는 예상 길이와 수율을 계산한다. 기존 자투리 재고 계산과 분리해 기존 확정 workflow의 안전성을 유지했다.

### 3.3 수동 배치 안전성

수동 배치 보정 로직을 별도 모듈로 분리했다.

- 5mm 그리드 스냅
- 좌우·시작·끝 여백을 포함한 경계 clamp
- 다른 조각과의 사각형 충돌 검사
- 회전 후 롤 폭·사용 길이 초과 검사
- 실패 시 원래 좌표 유지 및 사용자 메시지 표시

### 3.4 견적 계산

단일 작업 계산과 프로젝트 합산 계산을 분리했다. 프로젝트 합산 견적은 원단 비용과 시공 비용을 합산한 뒤 할인율을 한 번만 적용해 작업별 할인 중복을 방지한다.

그룹별 저장 단가가 있는 경우 기본 단가 요청 시 해당 단가를 우선 사용하며, 견적 화면에서 사용자가 입력한 전역 단가는 전체 합산 계산에 적용할 수 있다.

## 6. 현재 한계 및 리스크

1. 병합 롤은 새 원본 롤 생산 단위로 저장·색상 도면·조각 상세·전체 재단 완료 체크를 지원한다. 병합 롤을 자투리까지 포함하는 생산 방식으로 확장하려면 혼합 규격 자투리 배치 알고리즘과 별도 delta 설계가 필요하다.
2. 수동 배치는 배치 목록과 캔버스 직접 드래그를 모두 지원한다. 드래그는 기존 5mm 스냅·충돌 검증을 공유한다.
3. Cloudflare API는 코드와 스키마까지 준비됐지만 D1 ID, Access Team Domain/AUD, 사용자 도메인 설정과 원격 마이그레이션은 배포자가 수행해야 한다.
4. Cloudflare 환경 변수가 없으면 데이터는 기존 AsyncStorage에 저장된다. 서버 전환 후에도 JSON 백업·복원 경로를 유지한다.
5. 관리자 화면은 실제 권한 검사가 구현될 때까지 제한 상태다.

## 결론

현재 앱은 기존 사용자 workflow를 정적 웹 앱에서 사용할 수 있는 수준으로 통합했으며, 원단 절약·재고 안전성·프로젝트 재사용·견적 합산 측면이 크게 강화되었다. 다음 고도화의 핵심은 병합 롤을 실제 확정·도면·재고 트랜잭션 단위로 승격하는 것이다. 보안 인증과 서버 동기화는 UI만으로 해결할 수 없으므로 별도 백엔드 설계와 함께 진행해야 한다.
