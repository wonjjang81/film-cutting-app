# PWA 설치 및 독립 창 실행

## 점검 결과와 범위

기존 소스와 운영 로그인 HTML에는 manifest 링크, 설치 아이콘, 서비스 워커가 없었다. 이 변경은 설치 가능한 manifest, 192/512px 아이콘, Apple 홈 화면 아이콘, 설치 도움말과 안전한 업데이트 안내를 추가한다.

- Chrome/Edge: 앱 설치 안내 → 앱 설치 또는 브라우저 메뉴의 앱 설치.
- iPhone/iPad Safari: 공유 → 홈 화면에 추가 → 웹 앱으로 열기.
- 설치된 앱은 아이콘에서 별도 창으로 실행한다. 처음 설치/실행에는 HTTPS 연결이 필요하다.
- 운영 Cloudflare 버전의 Google 로그인·프로젝트 불러오기·저장은 온라인 기능이다. 네트워크가 끊기면 오프라인 안내를 표시한다. 완전 오프라인 편집/동기화 기능을 구현한 것은 아니다.
- 인증 응답·API·프로젝트 JSON·로그인 페이지를 캐시하지 않는다. 서버 인증/권한/저장소 설정을 변경하지 않는다. 앱 설치는 로그인 우회 수단이 아니다.
- PWA 설치 자체가 인증을 생성하거나 만료된 세션을 되살리지는 않는다. 로그인 유지 기간 변경은 별도 인증 기능이며 이 설치 기능 배포에 포함하지 않는다.
- 로컬 데이터의 자동 서버 동기화나 서버 데이터의 자동 기기 복제를 하지 않는다. 기존 JSON 백업/가져오기 절차를 유지한다.

## 배포와 캐시

루트 및 GitHub Pages 하위 경로에서 동일한 상대 manifest를 사용한다. 스크립트 경로를 기준으로 서비스 워커 scope를 제한한다. 탐색 HTML은 네트워크 전용이며 실패하면 정적 offline.html만 반환한다. 캐시는 공개 해시 정적 파일과 오프라인 안내/아이콘으로 제한한다.

새 서비스 워커는 자동으로 실행 중인 앱을 새로고침하지 않는다. 사용자가 프로젝트 저장 후 업데이트 버튼과 확인창을 승인하면 해당 창을 새로고침한다. 다른 창에서 업데이트를 승인해도 이 창의 미저장 입력은 강제 새로고침하지 않는다. build:web 마지막 단계에서 HTML·JS·manifest·아이콘의 해시로 서비스 워커 버전을 자동 지정하므로 앱 코드만 변경돼도 업데이트를 감지한다. public/sw.js의 v1은 빌드 시 치환하는 마커다. 이전 앱 자산을 지울 때는 이 scope의 film-pwa 캐시만 삭제한다. 브라우저 저장소 전체 삭제나 로그아웃 데이터 삭제는 하지 않는다.

검증: node scripts/pwa-browser-check.cjs 및 빌드 후 node scripts/cloudflare-build-check.mjs. 설치 프롬프트 노출은 OS/브라우저/설치 여부/브라우저 판단에 따라 달라 실제 OS 설치 확인은 별도다.
