# 필름 재단 앱 고도화 구현 진행 상황

기준일: 2026-08-16

작업 브랜치: `codex/continuous-roll-remnants`

## 현재 결론

연속 롤 방식의 원단 절약 우선 계산, 실제 크기 자투리 재고, 프리셋·작업 이력, CSV/PDF 작업지시서, 반응형 생산 화면까지 구현했다. 큰 입력은 브라우저 메모리를 보호하는 제한된 material-first 경로로 전환하며, 이 경우 화면과 저장 이력에 `원단 절약 계산(근사)`임을 명시한다.

현재 UI 통합 변경은 작업 트리에 있으며, 작업 확정 시 재고와 이력을 한 번의 저장으로 함께 반영하는 원자적 저장 경계까지 보완했다. 다만 이 마지막 보완 이후의 테스트 실행은 로컬 샌드박스 실행 제한과 계정 실행 한도로 차단되어 아직 커밋하지 않았다.

## 단계별 구현 상태

### 1. 연속 롤 자동배치 — 완료·커밋

- 원단 폭은 고정하고 길이를 연속으로 확장하는 생산 모델
- 우선순위: 새 롤 사용 길이 최소화 → 과생산 최소화 → 회전 수 최소화 → 패턴 전환 최소화 → 패턴 종류 최소화
- 작은 안전 입력은 exact 경로, 물리 하한 도달 시 certified 경로
- 큰 입력이나 탐색 예산 초과 입력은 폭과 수량에 대해 메모리가 제한된 material-first 경로
- 계산 결과에 `optimizationStatus`, `optimalityGapMm`, 후보·상태 수 메타데이터 제공
- 관련 커밋: `a4c506e8e`, `1cafd8c55`

### 2. 자투리 우선 사용 계획 — 완료·커밋

- 브랜드와 제품 번호가 일치하는 자투리만 후보로 사용
- 원본 폭보다 좁은 자투리도 실제 폭·길이 안에 제품이 들어가는지 독립 계산
- 새 롤 절감 길이 → 사용 면적 → ID/수량 순으로 결정론적 선택
- 남은 크기를 임의 환산하지 않고 보수적인 직사각형 right/bottom 잔여물로 저장
- 동일 규격 수량 일부만 사용하면 미사용 수량을 동일 ID로 유지
- 잔여 ID 충돌 방지와 오래된 재고 버전 거부
- 관련 커밋: `445be2adf`, `6fdc669bc`

### 3. 로컬 라이브러리 — 완료·커밋

- AsyncStorage 기반 버전 1 문서에 프리셋, 최근 작업 20건, 자투리 재고 저장
- 브랜드·제품 번호·실제 폭·실제 길이·수량·생성/수정 시각 보존
- 손상 문서 경고, 잘못된 날짜 거부, ISO 시각 UTC 정규화
- 한 저장소 인스턴스 내 변경 큐 직렬화와 stale 재고 검사
- 관련 커밋: `df04a07ff`, `0cabe23ee`

### 4. 작업지시서 내보내기 — 완료·커밋

- UTF-8 BOM CSV 생성
- 인쇄/PDF용 HTML 작업지시서와 신뢰 가능한 SVG 배치 도면 생성
- 브랜드, 제품 번호, 입력 규격, 자투리 사용, 결과, 최적화 상태 포함
- 관련 커밋: `ef12c2937`

### 5. 생산 화면 UI/UX 통합 — 구현·검증 완료, 커밋 대기

- 깔끔한 카드형 레이아웃과 360/768/1280px 반응형 구성
- 브랜드·제품 번호, 롤/제품 규격, 수량, 간격, 측면·시작/끝 여백, 회전 입력
- `원단 절약 우선` 모드와 exact/certified/approximate 상태 배지
- 연속 롤 행 패턴, 방향 색상, 배치 번호, 안전 여백 SVG 미리보기
- 자투리 실제 크기 저장·삭제, 현재 계산의 사용 예정과 절감 길이 표시
- 프리셋 저장·검색·불러오기·삭제, 확정 이력 불러오기·이름 변경·삭제
- 계산과 재고 반영을 분리한 `재고 미반영`/`작업 확정` 흐름
- 작업 확정 시 자투리 delta와 작업 이력을 한 번의 저장으로 원자적 반영
- CSV 다운로드와 PDF/인쇄 동작 연결
- 공통 하단 탭 바에서 `재단 계산`과 `관리` 라우트 모두 이동 가능
- 활성/비활성 색상, 아이콘, 키보드 자동 숨김, 모바일 안전 여백을 적용한 탭 바 스타일

## 검증 근거

- 전체 GREEN: 8개 테스트 파일, 102개 테스트 통과
- TypeScript 검사: 오류 없음
- Expo 웹 정적 export: 성공, 정적 라우트 생성
- 브라우저 수동 검증: 360px, 768px, 1280px에서 가로 넘침 없음
- 브라우저 업무 흐름 검증: 계산 → 자투리 저장 → 자투리 우선 재계산 → 작업 확정 → 이력 저장 → 프리셋 저장 성공
- 현재 `git diff --check`: 공백 오류 없음
- 원자적 확정 회귀 테스트 3개 추가: 단일 저장 성공, stale delta 전체 거부, 잘못된 작업 전체 거부
- 하단 탭 통합 후 전체 테스트·TypeScript·웹 export 재검증 완료

## 알려진 한계

- material-first 결과는 새 롤 길이의 전역 최적을 보장하지 않는다. 상태와 작업지시서에 approximate로 표시한다.
- 자투리 분할은 실제 절단 순서를 안전하게 설명할 수 있는 보수적 guillotine right/bottom 직사각형만 재고로 남긴다. 임의 다각형 nesting은 범위 밖이다.
- AsyncStorage 원자성은 단일 앱 인스턴스와 단일 저장 키 경계다. 여러 기기 동시 편집이나 서버 동기화는 지원하지 않는다.
- 인증·관리자 기능은 서버 검증 체계가 없으므로 비활성 상태를 유지한다.

## 배포 전 필수 조치

1. 다음 GitHub Pages 배포 전에 전체 테스트, TypeScript 검사, Expo 웹 export를 다시 실행한다.
2. UI 통합 변경을 검토하고 범위 파일만 커밋한다.
3. GitHub에서 과거 노출 개인 액세스 토큰을 폐기하고 `.env`, `guest_codes.json`, 인증 문자열, `node_modules` 이력을 제거한다.
4. 이력 재작성 뒤 기존 클론을 폐기하고 새로 클론한다.
5. 실제 계정·관리 기능이 필요하면 서버와 DB를 선정한 뒤 서버 세션 검증 방식으로 별도 구현한다.

클라이언트 정적 앱에는 비밀번호 검증, 관리자 권한 판정, 저장소 쓰기 토큰을 다시 포함하지 않는다.
