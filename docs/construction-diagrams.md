# 시공부위 도면

- 재단계산: 대그룹 입력 아래, 소그룹 입력 위에 도면선택 카드를 표시한다.
- 일반 도면선택은 기존 단순 장 일러스트를 사용한다. 상부장·하부장·냉장고장과 얇은 옆판·몰딩 위치를 유지하며 모눈으로 바꾸지 않는다. 장 추가/형태변경/삭제와 후드장 양문/싱글 변경을 지원한다.
- `/diagrams` 안에서 `시공부위 도면`과 `새 프리셋 제작 · 모눈`을 분리한다. 모눈은 새 프리셋 제작용이며 칸 채우기/지우기, 가로·세로 확장(각 최대 64), 형태 추가/변경/삭제, 이름 편집, 프리셋 저장/불러오기/삭제를 지원한다. 새 도면은 빈 모눈에서 시작하고, 새 프리셋 제작 시 확인 후 현재 편집 도면만 비운다. 저장된 프리셋은 유지한다.
- 지원 형태: 옆판, 밑판, 윗판, 몰딩, 양문장, 싱글장, 걸레받이, 서랍장, 후드장, Empty.
- 모눈은 위치·형태 확인용이다. 실측치수나 재단수량을 그림 크기로 추정하지 않는다. Empty는 치수 입력/조각 생성 대상이 아니다.
- 선택 후 `치수 입력`을 누르면 현재 대그룹의 같은 시공부위 소그룹에 조각 1개를 추가한다. 소그룹명은 `상부장`/`하부장`처럼 짧게, 조각명은 `상부장_U-SL_01`처럼 부위명·도면ID·순번으로 표시한다. 같은 ID를 다시 선택하면 기존 조각을 연다. 이전 방식으로 저장된 연결·실측값은 삭제하지 않는다. 실측치수는 사용자가 입력한다.
- 신규 양문장 조각 수량은 2, 싱글장·구조부는 1이며 후드장은 양문/싱글 설정을 따른다. 기존 조각을 재선택해도 수동 입력한 수량은 덮어쓰지 않는다. `＋ 시공부위 추가`로 `상부장2` 등 별도 위치 소그룹을 만들고 입력 대상을 선택할 수 있다. 같은 도면 ID라도 소그룹이 다르면 별도 조각으로 입력한다. 두 위치의 실측치수가 다를 수 있으므로 개소 배수와 달리 각각 입력하며, 새 소그룹 개소는 기본 1이다.
- `diagramShapeKey`는 작업 저장/복원, 견적 입력 스냅샷, 프로젝트 JSON 백업에 보존한다. 소그룹 이름 변경과 별개다. 프리셋을 적용하면 새 형태 ID를 생성하며 기존 소그룹을 임의 삭제하지 않는다.
- 도면/프리셋은 계정 ID별 현재 기기·브라우저의 AsyncStorage에 별도로 저장한다. 기존 모눈 도면 키는 그대로 보존하고 일반 장 도면은 별도 `:cabinets` 키를 사용한다. 기존 프로젝트 서버 데이터를 덮어쓰지 않는다. 장을 삭제해도 연결된 기존 소그룹 입력은 삭제하지 않는다. 서버 동기화/기기간 공유는 이번 버전에 포함하지 않는다. 저장 전 이전 상태를 `:backup`에 보존한다. 손상된 원본은 덮어쓰지 않고 오류를 표시한다.
- 웹 전용 편집판은 `allow-scripts`만 허용된 sandbox iframe과 네트워크 차단 CSP로 격리한다. 부모 화면이 송신 창과 스키마를 검증한 메시지만 저장한다. iframe에는 인증 토큰과 프로젝트 데이터를 전달하지 않는다.

검증: TypeScript 검사, 전체 Vitest 테스트, Cloudflare 빌드 확인. 브라우저 검증은 API를 모의 응답으로 대체하므로 운영 서버 데이터에 쓰지 않는다.

```powershell
$env:PLAYWRIGHT_MODULE='<설치된 playwright 모듈 경로>'
node scripts/construction-diagrams-browser-check.cjs
```
